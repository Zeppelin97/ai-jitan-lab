# プレイブック（分析部が毎週更新）

## PDCAの回し方
- **Plan**：2週間ごとに「試すこと」を1つだけ決める（複数を同時に変えると原因が分からないため）
- **Do**：毎日20時にリール1本。各投稿の post.json の `experiment` に、どのパターンかを記録する
- **Check**：毎週月曜にインサイトを取得して比較する（投稿から48時間以上たったものだけを使う）
- **Act**：判定基準を満たした方を「勝ちパターン」に移し、次の2週間の実験を決める

## 見る指標（優先順）
1. **シェア率** = shares ÷ reach（新しい人に届く力。最重要）
2. **視聴維持率** = ig_reels_avg_watch_time ÷ 動画の長さ（最後まで見られているか）
3. **フォロー率** = follows ÷ reach（アカウントの魅力）
4. **保存率** = saved ÷ reach
※ いいね数・フォロワー数は参考程度

## 判定基準
- 各パターンにつき4本以上のデータがそろってから判定する
- 主指標（シェア率）で30%以上の差があれば、良い方を採用する
- 差が30%未満なら「差なし」として、作りやすい方を採用する
- データが足りない・期間中に大きな外れ値（1本だけのバズ）があれば、判定を次の週に持ち越す

## 実験1（2026-11-16〜11-29）：冒頭の問いかけの型
| 型 | 例 |
|---|---|
| A：なぜ型 | 「なぜ会議では誰も発言しないのか？」 |
| B：共通点型 | 「会議で発言しない人の共通点」 |
| C：意外な数字型 | 「8人で綱を引くと力は半分になる」 |
- ~~A→B→C の順に毎日ローテーションする~~ → **2026-11-16 週次レビューで変更**（下の「型の公開順」に従う）
- 判定は 11/30（月）の週次レビュー。途中経過は 11/23（月）に確認

### 型の公開順（2026-11-16 決定）
11/30 09:00 の判定で使えるのは 11/27 20:00 までの公開分（48時間ルール）。A→B→C の単純ローテーションでは B・C が3本ずつで「4本以上」に届かないため、11/27 までに A・B・C を各4本そろえる順番に変える。

| 日付 | 型 | pillar |
|---|---|---|
| 11/16 | A | 職場（作成済み） |
| 11/17 | A | 認知バイアス（作成済み） |
| 11/18 | A | 人間関係（作成済み） |
| 11/19 | **B** | 職場 |
| 11/20 | **C** | 職場 |
| 11/21 | B | 人間関係 |

| 11/24 | B | 認知バイアス |

- 同じ型に同じ pillar が偏らないよう、B・C それぞれに職場／人間関係／認知バイアスを混ぜる（型の差とテーマの差を区別するため）
- 1日の投稿が欠けたら、翌日以降は表の順番をそのまま後ろにずらす（型をスキップしない）

### 実験1期間中のルール
- **フォーマットはリールに統一**（`config/brand.json` の `reel.carousel_per_week` を 2→0 に変更。カルーセルは視聴維持率が取れず比較のノイズになるため）。11/30 の判定後に 2 へ戻すか検討
- **恋愛・友人関係（10%）と PR（5%）は 11/27 まで出さない**（本数が少なく比較のノイズになる。PR はアフィリエイト登録が未完了）

## データ取得の課題（分析部の指摘・2026-11-16）
- `data/insights.csv` に `experiment_variant`・`published_at` 列がなく、post.json と突き合わせないと型別集計・48時間判定ができない。列追加時は `fetch_insights.py` が見出し不一致で旧データを消すので、データが入る前（今週中）に対応するのが安全
- アカウント単位のリーチを取得していない（`fetch_account.py` はフォロワー数・投稿数のみ）
- 取得に失敗した指標は空文字で保存される → 集計では 0 ではなく欠損として扱う
- インサイト取得は `content/queue/*/post.json` だけが対象。公開済み投稿を archive に移すと取れなくなるので、移さないこと
